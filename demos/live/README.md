# FabricSandbox · 课程汇报现场演示

本目录包含三种可交互的展示：**实时网络规划计算、本机真实 TCP 故障恢复、3090 历史实测证据回放**。它们共用“输入与初始方案 → 异常 → 诊断 → 候选及拒绝理由 → 所选方案 → 执行 → 新进度与验证”的讲解顺序，但证据来源各自独立。普通笔记本即可运行；无需 GPU、服务器连接、互联网或外部大模型。

## 1. 启动

要求：电脑已经安装 **Python 3.10 或更新版本**，使用现代浏览器。本演示使用 Python 标准库与目录内的项目源码，不需要 `pip install` 或下载模型。

### macOS

双击本目录的 `启动演示.command`。也可以从仓库根目录在终端启动：

```sh
cd demos/live
./启动演示.command
```

启动器依次查找 PATH 中的 `python3.12`、`python3.11`、`python3.10`、`python3`，并检查版本。它不会自动安装软件。

### Windows

把**整个目录**复制到电脑上，双击 `start_demo.bat`。启动器优先使用 `py -3`，其次使用 `python`、`python3`，均需通过 Python 3.10+ 版本检查。

### 通用命令

在本目录执行（将 `python3` 换成已有 Python 3.10+ 的解释器）：

```sh
python3 server.py --port 0 --open
```

`--port 0` 由操作系统分配空闲端口，浏览器会自动打开。以终端打印的 `http://127.0.0.1:端口` 为准；本次地址也写入 `runtime/server.json`。需要固定端口时可以改用 `--port 8765`；如端口被占用，恢复使用 `--port 0`。

不要直接双击 `web/index.html`：页面需要本地 Python 服务计算方案、启动 TCP 实验并读取证据。演示期间请保留启动终端。

## 自定义网络拓扑（2026-11-04 新增）

原有“两机架、四节点、八张 GPU”默认演示入口保留。在“网络方案评估”中选择“自定义 JSON”，可以粘贴拓扑或导入 `.json` 文件，然后校验并点击原来的“分析当前方案”。“采用推荐方案”仍按分析时冻结的输入重新仿真。切换回默认模式即可继续原来的带宽与资源状态演示。

- 可直接导入 `examples/topology_3racks.json`：3 个机架、6 个节点、12 张 GPU。页面也提供三机架示例。
- 可以修改节点所属机架、每节点 GPU 数量与每卡显存，以及节点带宽、机架上联带宽、机内带宽和延迟。自定义模式以 JSON 为准，不叠加默认模式的带宽/资源快捷控件。
- 支持 1–16 个节点，每节点 1–8 张 GPU，总计至多 64 张。当前规划演示固定为两个各 4 卡的 DDP 作业，所以分析至少需要 8 张物理 GPU；多出的卡可空闲。拓扑校验本身允许更小的拓扑。
- 自定义拓扑使用三个确定性放置候选，按相同的负载与拓扑比较；默认入口仍保留原有九候选。有限候选不能保证全局最优。
- 修改输入会使旧的分析和推荐失效，需要重新分析。导出记录包含实际输入的拓扑、放置及哈希。

这里仍然是“节点归属机架”的二层有效带宽模型。JSON 不接受任意交换机、链路边列表或路由协议；每一类资源使用全局统一的带宽参数。自定义拓扑只作用于网络仿真，真实 TCP 演示和历史 GPU 证据仍有各自独立的数据来源。

若服务已运行，请在原启动终端按 `Control+C`，再重新打开 `启动演示.command`，刷新浏览器以加载新接口。接口调用示例见 `MODEL_API.md` 的“自定义拓扑接口”。

## 2. 三分钟汇报顺序

### 第一分钟：动态网络规划

1. 打开“网络方案评估”，保持 **50 Gbps、完整资源**，点击“分析当前方案”。
2. 对照拓扑说明两组 DDP 作业如何占用 8 张 GPU，跨机架通信怎样竞争共享上联容量。指向诊断中的具体容量样本与输入版本。
3. 展示可行候选与被拒绝的候选：同一 GPU 不能同时分给两组任务；每组需要完整的 4 卡通信组；显存、节点健康与连通性必须满足约束。
4. 说明选择规则：在声明的有限候选中，先选择仿真完成时间最短者，再比较移动数量，并按候选 ID 确定性地处理同分。
5. 点击“采用推荐方案”，展示使用冻结输入重新执行仿真后的结果与校验。原方案与新方案保持相同负载、拓扑、故障和评估时长。
6. 可选追问：切换 25 / 100 Gbps 后重新分析，说明带宽为什么影响结果；切换“显存不足”或“节点 n0 不可用”，展示有依据的等待 / 不可行结论。

可用讲稿：“这里每次点击都会运行原项目的离散事件仿真与约束校验。我们展示规划决策的过程及其可验证性。数值采用合成参数，不能当成 3090 实测耗时；选优范围是页面列出的候选。”

“采用方案”是按冻结输入启动一次新仿真，不是把正在运行的 GPU 训练作业在线迁移。

### 第二分钟：真实 TCP 故障与恢复

1. 切换“真实通信故障”，点击“启动真实通信”，先观察实际进程 PID、端口、ACK 块数与数据量增长。
2. 保持“主通道故障”，点击“注入故障并自动恢复”。系统会终止本实验自己启动的主通道 A 进程。
3. 依次点击七个步骤，讲解：初始路径 → 真实异常 → 探测和传输失败证据 → 候选 / 拒绝理由 → 选择备用 B → 更新计划并执行 → 新数据获得接收端 ACK。
4. 指向时间日志、方案版本、SHA256 校验和恢复后的新进度，说明恢复结论如何由新的传输证据确认。
5. 可选展示“主备均故障”：启动新实验后注入该故障，展示无健康通道时的受阻结论，不宣称恢复成功。

可用讲稿：“这是当前电脑上真实运行的 TCP 进程与数据传输。规则 Agent 根据实际探测与传输证据做出决策；恢复由切换后新数据的校验和 ACK 确认。”

所有通信都位于 `127.0.0.1`。它验证应用层的监测、决策、执行与验证流程，不等同于物理交换机、跨主机 GPU 网络或 RDMA 故障。画面动画只辅助理解，诊断与计数以后台实验记录为准。

### 第三分钟：3090 实测证据

1. 切换“3090 实测证据”，明确说明这里回放的是已有服务器实验，当前电脑不执行 GPU 训练。
2. 按七步查看同一个恢复事件，说明初始使用 GPU **2 / 3**，GPU 3 的 worker 异常退出后选用 **2 / 4** 重新组成通信组。
3. 说明真实运行的是 **GPT-2 small 结构、随机初始化、合成 token 数据**的 DDP 训练，不是预训练模型质量评测。
4. 展示从 **step 5 checkpoint** 重新启动，随后出现新的 **step 6、step 8，最终 step 20** 的证据。强调“进程启动”本身不能证明恢复，必须检查新进度与完成记录。
5. 打开来源文件与 SHA256，说明展示内容能够回到脱敏后的公开证据副本；物理设备标识使用一致代称。

可用讲稿：“这部分补充真实 GPU 训练的领域约束：DDP 要恢复完整通信组，checkpoint 之前与之后的进度不能混淆。我们用重建后的新训练步和最终完成状态确认恢复，而不是仅凭启动命令返回。”

## 3. 三种模式的证据边界

| 模式 | 当场实际发生什么 | 可以证明什么 | 不能直接证明什么 |
|---|---|---|---|
| 网络方案评估 | Python 运行原项目离散事件仿真、候选枚举、约束校验与方案重算 | 显存 / 完整组 / 健康 / 共享容量如何影响规划；固定输入下的模型对照 | 真实 GPU 性能、跨主机带宽或生产集群收益 |
| 真实通信故障 | 创建本机 TCP 进程并传输数据；终止通道进程；探测、选路、校验新传输 | 应用层监测—诊断—决策—执行—验证的可运行过程 | RDMA、物理链路、NCCL 或 GPU worker 的当前故障 |
| 3090 实测证据 | 读取项目目录中已导出的、带来源与指纹的服务器记录 | 当次真实 DDP 训练故障与 checkpoint 恢复事实 | 当前笔记本正在运行 GPU 训练；模型推理或训练质量 |

Agent 使用可解释规则与工具调用，**离线运行，不依赖 LLM**。三种模式展示共同的系统设计，但没有被包装成一个自动控制真实 GPU 集群的程序。

## 4. 结束与导出

- 右上角“导出本次记录”将当前方案、计算结果与 TCP 会话状态等导出为 JSON，保存位置由浏览器下载设置决定。
- TCP 原始日志位于 `runtime/tcp/<session_id>/`；每次启动使用独立会话目录。单次会话默认最长运行 5 分钟。
- 演示结束先点击“停止实验”，再在启动终端按 `Control+C`。关闭浏览器标签页不会自动关闭 Python 服务。
- 不要把 `runtime` 中旧会话的日志当成当前会话；现场以页面会话 ID 和时间戳为准。

### 仓库中的代码对应关系

演示保留独立 `vendor` 快照，因此只复制 `demos/live` 也能启动。仓库维护时按以下关系核对源文件：

| 演示快照 | 仓库根目录中的对应源文件 |
|---|---|
| `vendor/fabric_sim/*.py` | `packages/fabric-sim/src/fabric_sim/*.py` |
| `vendor/agent_demo/{__init__,common,contracts,controller,tcp_backend,tcp_worker}.py` | `agent_demo/` 中的同名文件 |

`vendor/fabric_sim_source.json` 和 `tcp_source_provenance.json` 记录未改动内核的 SHA256，当前位置以仓库根目录为基准，历史来源路径已匿名化。`data/gpu_sources.json` 则校验脱敏后的 GPU 公开证据及重新提取的展示数据，不代表原始导出的字节摘要。此次处理没有重新执行 GPU 实验；公开设备标识仅用于跨记录的一致性复核，见 [脱敏说明](../../docs/PRIVACY.md)。从仓库根目录运行 `python3 scripts/check_repository.py` 可核对来源与文件完整性。

### 重新导出 GPU 历史展示资料

日常演示直接读取随仓库提供的 `data/`。维护脚本默认查找仓库根目录下的 `evidence/gpu-case1`，目录缺失时会明确报错；也可通过 `--bundle` 指定包含 `gpu_matrix_01/gpt2_recover` 的原始证据目录。

在本目录执行：

```sh
python3 scripts/export_gpu_evidence.py --bundle ../../evidence/gpu-case1
```

新导出写入 `build/gpu-evidence-export/`，不自动覆盖已有 `data/`。核对同一事件、来源指纹和展示内容后，维护者才应显式使用 `--output data` 更新展示资料；导出不会执行 GPU 任务或复制检查点权重。

## 6. 如何说明系统实现复杂性

- **结构复杂性**：界面只发结构化请求；HTTP 服务冻结输入并管理会话；规划适配器负责候选与约束；原仿真内核负责容量竞争计算。TCP 模式复用原 Controller 的 observe / diagnose / propose / validate / apply / verify 工具链，执行器返回回执与独立验证证据。
- **行为复杂性**：分析生成独立 run_id；采用方案使用这份输入，不能偷偷改参数。真实实验使用独立 session_id；旧会话的注入或停止请求被拒绝。界面也用请求代次隔离迟到响应。停止、重启或超时只清理本会话拥有的进程。
- **领域复杂性**：网络规划同时满足显存、GPU 独占、健康资源和完整通信组约束；容量由通信流共享。GPU 实测说明 DDP 必须重建完整组、从已提交检查点恢复，并用新代次进度证明恢复；TCP 的 ACK 不被冒充为 GPU 训练验证。

## 7. 已验证与尚未覆盖

2026-11-04 自定义拓扑更新：原适配器 8 项回归、自定义拓扑 9 项、进程内 HTTP handler 8 项检查全部通过。覆盖默认数值不变、不同机架归属和带宽实际影响结果、输入哈希冻结、非法拓扑拒绝、64 GPU 边界，以及未完成候选禁止采用。前端另通过 10 项轻量 DOM 交互检查，使用真实仿真输出作为响应样本。

2026-11-07 仓库整理复核使用无需监听端口的测试：实际 HTTP handler 由内存字节流驱动，前端使用实际模型生成的响应样本。此复核不验证真实 socket 传输、GPU 执行或浏览器 CSS 排版。

无需端口的验证命令（在本目录，Python 3.10+）：

```sh
python3 -m unittest discover -s . -p test_demo_model.py -v
python3 -m unittest discover -s tests -p test_custom_topology.py -v
python3 -m unittest discover -s tests -p test_topology_inprocess.py -v
```

真实监听环境可额外运行 `python3 -m unittest discover -s tests -p test_topology_http.py -v`。测试使用独立临时端口，不会启动 TCP 故障演示的子进程。

若装有 Node.js，可用 `python3 build/generate_topology_fixtures.py` 生成当前模型的真实响应样本，再运行 `node build/topology_ui_check.mjs` 复现前端交互检查；此检查不验证浏览器 CSS 排版。记录见 `audit/topology_ui_checks.json`。

原版本曾完成 5 项真实 TCP 后端集成检查，以及包含真实 ACK、冻结输入和旧会话隔离的 HTTP 检查。这些历史结果不等于本次仓库整理重新执行；旧运行日志没有作为当前验证记录迁入本目录。允许本机监听的环境可运行 `python3 -m unittest discover -s tests -p test_tcp_runner.py -v` 与 `python3 -m unittest discover -s tests -p test_http_demo.py -v` 重新核验，它们会创建并清理自有 TCP 进程。
